**Plan first.** Show the plan in chat, write it in the same turn to `biblio/scratchpad/{slug}/prd.md` and say where it is. It has four parts: Problem (what is wrong or missing), Expectation (what is true once solved), Objective (what the work sets out to do, and what is out of scope) and Plans (design decisions, then the phases in build order, each a `- [ ]` item). Start `activities.md` beside it. A small task gets a short PRD, not none.{existing}

- A phase is an agreed, testable deliverable. A task can have several, but split into phases only when it spans multiple domains or distant features. A bunch of smaller actions within one domain is one phase. Steps go inside their phase as sub-items. Mark a phase `(review)` only when the user asked to look at it before the next one starts, or when a later phase depends on how it turns out.
- Write Plans as the simplest reading of the Objective. Every item must be needed to meet an Expectation. If a similar function or an earlier feature suggests adding more, tell the user in one or two sentences with your recommendation and add it only after a yes, because whoever resumes the PRD reads it as the spec.
- State how the work is done: a workgroup for a multi-phase, high-value task, subagents for mostly read-only research or a refactor that needs only writes, solo for a task spanning few files or domains.
