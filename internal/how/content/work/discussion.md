# Working a discussion

An idea, a question about the project, or a design talk with the user, with no task file yet.

1. **Gather context before you answer.** Read `biblio/books/toc.md`, the books whose names or tags relate, then the code no book covers. Do this before you give an opinion, a proposal or a recommendation. A plain question that needs no judgment can skip it.
2. **Collaborate.** The user thinking out loud is not a final design and not an instruction. Build on the idea, say plainly what you see, and give a recommendation rather than a survey of options. A question is answered, not acted on.
3. **Nothing outside `biblio/` changes** in a discussion.
4. **Persisting it.** "Wrap it up" means writing the idea to `biblio/scratchpad/<slug>/notes.md` with an `activities.md` beside it, loose is fine. Once the user decides to build it, run `lgrass how work task <slug>`; to investigate it first, `lgrass how work research <slug>`.
